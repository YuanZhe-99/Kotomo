# 编译后的跨语言词库

跨语言词库把用一种语言键入的内容对应到日文词：拼音对应汉字词，英文词对应外来语与同义词。
`lexicon/CrossLexicon.java` 把它生成为两张文本表；应用从不读取它们。一个主机工具把它们编译成一个只读文件
`cross.klx`，混合输入协调层把它映射进内存、按键查找。这是**格式第 1 版**（`core/mixed/cross_lexicon.h`
中的 `kLexiconVersion`）。

## 构建

```bash
java -Xmx4g lexicon/CrossLexicon.java    # build/lexicon/pinyin-ja.tsv and en-ja.tsv
cmake -S core/mixed -B build/host/mixed -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/host/mixed --target kotomo_lexicon_compile
build/host/mixed/kotomo_lexicon_compile build/lexicon/pinyin-ja.tsv build/lexicon/en-ja.tsv build/lexicon/cross.klx
```

编译器拒绝含有坏行的表并指出那一行（不足八列，键、表层形式或读音为空，字符串超过 255 字节，代价不在
0–65535 之内，未知的类别），并在报告成功之前把自己的输出重新映射一遍。应用的构建把
`build/lexicon/cross.klx` 不压缩地打包为资产 `cross.klx`；没有这个文件时应用照常构建、但没有跨语言转换，
`KOTOMO_REQUIRE_LEXICON=1` 使它的缺失成为错误。这个文件是构建产物，从不提交；它沿用所派生数据的许可证
（`third-party.md`）。

## 布局

所有整数为小端。各段依次相接，没有填充。

| 段 | 内容 |
|---|---|
| 头部，32 字节 | `KOLX`；u32 版本；u32 拼音键数；u32 英文键数；u32 条目数；u32 字符串段的大小；u32 最长键的长度；u32 零 |
| 拼音键 | 每个键一条记录，外加一条哨兵：u32 键在字符串段中的偏移，u32 该键第一个条目的序号。一个键的条目止于下一条记录的起点；哨兵记录最后一个键的终点 |
| 英文键 | 同上，用于英文 → 日文表 |
| 条目，每条 12 字节 | u32 表层形式的偏移，u32 读音的偏移，u16 代价，u8 音节数，u8 类别 |
| 字符串 | 每个不同的字符串只存一次：一个长度字节，然后是相应字节数的 UTF-8 |

键在各自的表内按字节排序，所以查找就是在键记录上二分；一个键的条目按代价、再按表层形式排序。拼音表的条目
在前，英文表的条目在后。

| 条目字段 | 含义 |
|---|---|
| 表层形式 | 日文词 |
| 读音 | 它的平假名读音 |
| 代价 | 该条目在 Mozc 中的词代价；越低越常用 |
| 音节数 | 对拼音键，是它的音节数；否则为 0 |
| 类别 | 0 拼音 → 日文；1 英文 → 同义的日文词；2 英文 → 它的片假名外来语；3 英文 → 造出来的片假名拼写 |

文本表中的词性 ID 不在文件里：一个词作为固定片段进入转换时，Mozc 的胶水层按读音与表层形式自己查出它的 ID。

## 读取

协调层把文件只读映射（就地从 APK 中、按资产的偏移），启动时什么都不解析；一次查找只触及它读到的页。这个文件
是一处边界：读取方在打开时检查魔数、版本以及各段大小之和等于文件大小，并在跟随每个偏移、范围与类别时检查
它们。损坏的文件什么都查不到，绝不读到映射之外。读取方拒绝任何其他版本。

## 版本

布局或字段含义的任何改动，都在同一组变更中同时提高编译器与读取方的版本；这个文件随应用重新构建，所以不存在
迁移。
