# 引擎 ↔ 应用契约

应用与原生引擎怎样交互：输入什么、输出什么，以及混合输入协调层（`core/mixed/`）怎样调用三个引擎。这是
**契约第 3 版**（`core/mixed/snapshot.h` 中的 `kContractVersion`，`engine/Snapshot.kt` 中的
`Snapshot.VERSION`）。两侧都已存在：引擎一侧是 `libkotomo_core.so`（`core/mixed/session.h`、
`jni/core_jni.cc`），应用一侧是外观类 `engine/Core.kt` 与解码器 `engine/Snapshot.kt`。混合模式运行在它
之上；中文、日文与英文模式仍然调用各自引擎的外观类（`engine/Rime.kt`、`Mozc.kt`、`English.kt`）。相关的
决定是 ADR-008 与 ADR-009（`decisions.md`）。

## 形态

- 一个 Kotlin 外观类对应一个原生库，只在引擎线程上调用。协调层就是这个库；它通过 librime、Mozc 与英文核心
  这些库的普通 C 函数调用它们，所以无论一次按键问了几个引擎，都只跨一次 JNI。
- 输入：一个请求，即一次按键或一条命令，带上应用自己计数的代号，编码成字节。输出：一份快照，编码成字节。
  不用 JSON，也没有逐候选的 JNI 调用。
- 引擎在请求之间保存组合：键入的字母与分隔符、每个键被按在哪里、选项与上下文。
- 契约中的任何调用都不学习。选择只说明要提交什么；学习发生在提交时，由之后的调用完成，敏感输入框永不学习。

## 输入：请求

整数一律小端。字符串是一个 `u16` 字节长度加 UTF-8 字节。

| 字段 | 类型 | 含义 |
|---|---|---|
| 魔数 | 2 字节 | `KR` |
| 版本 | u16 | 契约版本；引擎拒绝其它版本 |
| 代号 | u64 | 应用对按键与命令的计数；快照原样带回 |
| 命令 | u8 | 下表的代码之一 |
| 字段 | | 该命令自己的字段，按所列顺序 |

| 代码 | 命令 | 字段 | 效果 |
|---|---|---|---|
| 0 | 设置组合 | 字符串：组合 | 替换整个组合（切换模式时交接字母）；截断到 256 字节 |
| 1 | 按键 | u32 码位；i16 x、i16 y：在英文引擎 1000 × 600 的布局空间中的按下位置，没有时为 −1 | 追加一个字母，或作为边界提示的空格或撇号；其它字符与超过 256 字节的按键不改变任何东西 |
| 2 | 退格 | — | 删除最后一个字符 |
| 3 | 清空 | — | 丢弃组合，不提交 |
| 4 | 选项 | u8 智能程度（0 保守，1 平衡，2 积极）；u8 开关；u8 目标语言；i8 × 3 中文、日文、英文的权重 | 开关的各位：0 拼音 → 日文，1 英文 → 日文汉字词，2 英文 → 片假名，3 较长组合内部的跨语言词（关闭：只作为整个组合），4 输入框不得留下痕迹（Mozc 以无痕方式转换）。目标语言的各位指明候选可以用哪些语言书写：0 中文，1 日文，2 英文；混合模式三位全开，日文模式只开日文并取其中的跨语言候选（第 3 版）。权重表示用户把该语言的权重从默认值移动了多少，−100…100；每一点对该语言的候选相当于 40 个代价单位 |
| 5 | 上下文 | 字符串：光标前的文本 | 留作按上下文排序之用；目前没有读取方。敏感输入框中应用永不发送 |
| 6 | 选择 | u64：屏幕上那份快照的代号；u16：候选在其中的序号 | 提交该候选：快照的提交字段是它的文字，组合为空。引擎的上一份快照是另一份，或其中没有这个候选时，什么都不提交 |

每个请求都以它留下的组合的快照作答。引擎无法解码的请求（其它版本，未知的命令、智能程度或开关位，超出范围的
权重，被截断或过长的缓冲区）得不到快照，也不改变任何东西。协调层无法转换的组合（没有字母，或有字母与分隔符
以外的字符）得到只有组合、没有候选的快照。

第 3 版没有的：选择或锁定单个片段、提交组合的一部分、撤销转换与恢复输入串（快照已带有这些命令所指的片段），
以及在组合内移动光标。它们各自随新的契约版本到来。

## 输出：快照

一份快照描述一次请求之后应用显示的内容：先要提交的文字、组合、光标与候选，最好的在前。每个候选覆盖整个
组合，并保留它的片段：每个片段对应组合中的哪一段、它的文字、读音、这一段是用哪种语言输入的，以及文字的
来源。之后的修改锁定或更换的就是这些片段，所以其它片段不会被重写。

| 字段 | 类型 | 含义 |
|---|---|---|
| 魔数 | 2 字节 | `KS` |
| 版本 | u16 | 契约版本；解码方拒绝其它版本 |
| 代号 | u64 | 请求的代号 |
| 阶段 | u8 | 同一代号的首批候选为 0，之后的阶段从 1 起 |
| 输入 | 字符串 | 输入时的组合 |
| 光标 | u16 | 光标在组合中的字节偏移 |
| 提交 | 字符串 | 这个请求提交到输入框的文字；多数请求为空 |
| 候选数 | u16 | 其后是这么多个候选 |
| 候选：文字 | 字符串 | 选中它时提交的内容 |
| 候选：目标语言 | u8 | 它用哪种语言写成：0 中文，1 日文，2 英文 |
| 候选：代价 | i32 | 引擎的代价，小的在前；只在同一份快照内可比 |
| 候选：标志 | u8 | 第 0 位跨语言，第 1 位模糊或纠错，第 2 位 Emoji，第 3 位覆盖整个组合 |
| 候选：片段数 | u16 | 其后是这么多个片段，按输入顺序 |
| 片段：起、止 | u16、u16 | 片段对应的组合字节范围 |
| 片段：文字 | 字符串 | 这个片段提交的内容 |
| 片段：读音 | 字符串 | 日文片段为平假名，其它为输入的字母 |
| 片段：输入语言 | u8 | 这一段是用哪种语言输入的（0、1、2 同上） |
| 片段：来源 | u8 | 0 librime，1 Mozc，2 英文词典，3 拼音 → 日文词库，4 英文 → 日文词库，5 协调层的规则（助词 は、を、へ） |
| 片段：固定 | u8 | 片段作为固定值进入 Mozc 时为 1 |

解码方检查一切：魔数、版本、每个长度是否超出缓冲区、每个字符串是否为 UTF-8、语言与来源是否在取值范围内、
光标与每个片段的范围是否在组合之内，以及没有多余的字节。任何一项不通过，整个缓冲区作废。

计划中的统一候选这样对应到快照：文字、目标语言与代价是候选的字段；原始输入范围、来源语言、读音、词库来源
与分段信息在片段里；模糊、跨语言与 Emoji 是标志。匹配置信度就是代价。Emoji 仍由应用加入
（`Candidates.mixed`），排在引擎的候选之后、由 Emoji 权重决定的位置；目前没有快照携带 Emoji。

## 过期的更新

应用记着屏幕上那份快照的代号与阶段。新的快照只有在代号更大，或代号相同而阶段更大时才取代它
（`core/mixed/snapshot.h` 中的 `Replaces`，应用中的 `Snapshot.replaces`）。其它情况一律不读取就丢弃：
对旧按键迟来的回答永远不会覆盖对新按键的回答，各语言一致。选择命令指明它所依据的代号，也是出于同样的原因。

## 协调层背后的引擎

协调层不链接任何引擎，也不解析其它库的任何符号。它只问五个问题（`core/mixed/engines.h`）。每个引擎库都有
一张静态的普通 C 函数表来回答自己的问题，并通过一个 JNI 取值函数返回这张表的地址（`Rime.api()`、
`Mozc.api()`、`English.api()`）；`Core.open` 把这些地址连同 Mozc 与英文引擎的句柄交给协调层的库，后者
经由它们调用（`core/mixed/device/api_engines.h`）。每张表以版本号开头，协调层拒绝不是为它构建的版本。
各库仍然只导出自己的 JNI 入口。不存在的引擎（没有 Mozc 的构建）就是缺失的表：它的问题什么都查不到，其它
语言照常工作。

| 问题 | 由谁回答 | 函数表 |
|---|---|---|
| 这些字母的开头拼出哪些拼音音节 | 会话所用方案的 librime 拼写表（prism），在会话打开时映射，所以模糊音与纠错规则同中文模式一样生效 | `core/rime/jni/kotomo_rime_api.h`：`spellings` |
| 转换这一串音节 | librime 的会话，音节之间用撇号连接 | `kotomo_rime_api.h`：`convert` |
| 把这段罗马字映射为平假名 | Mozc 的罗马字表 | `core/mozc/kotomo_mozc_api.h`：`hiragana` |
| 在固定这些片段的前提下转换这段读音 | Mozc 的转换器（`MozcEngine::PinnedConvert`） | `kotomo_mozc_api.h`：`convert` |
| 这是不是一个英文词，有多常用 | 英文词典，精确查找 | `core/english/jni/english_api.h`：`lookup` |

任何回答都不学习，除 librime 之外也都不在调用之间保留状态：协调层在 librime 唯一的会话里转换，会替换并
清空它的组合，所以混合模式把自己的组合保存在协调层中，中文模式的组合从不与它同时存在。在主机上，转换语料
把四个库加载进同一个 JVM，跨过同一条边界（`tests/conversion/run.sh`）；协调层自己的语料运行器直接链接
librime 与英文核心，并经一个行服务（`core/mozc/kotomo_mozc_service.cc`）访问只能在自己的 Bazel 工作区
内构建的 Mozc，这个行服务不属于本契约。

## 版本

字段、编码、命令、标志或来源取值的任何改动，都在同一个变更中提升两侧的契约版本并更新两侧的测试。读到其它
版本的一侧丢弃缓冲区；不跨版本猜测。各引擎的函数表有各自的版本（`KOTOMO_RIME_API_VERSION` 及其同类），
随表的任何改动而提升。
