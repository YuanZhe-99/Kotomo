# Upstream contracts

What Kotomo relies on from its upstreams, and how far each point has been checked. The upstreams
follow their latest releases, so every point is re-checked when its upstream moves. The points
below were read in the upstreams' repositories, source and documentation on 2026-11-04, without
building or running anything; P0 re-checks each one and replaces "read" with the result.

## librime

| Point | Consequence | Checked |
|---|---|---|
| BSD-3-Clause; CMake and C++17; needs Boost ≥ 1.74, LevelDB, marisa, OpenCC ≥ 1.0.2 and yaml-cpp ≥ 0.5 (glog optional) | built from source as a submodule with the NDK | read |
| The embedding API `rime_api.h`: sessions, `process_key`, `set_input`, `get_context` (preedit, cursor, candidate page), `get_commit`, candidate selection and iteration, `set_option`, `register_module` | a pinyin span converts through `set_input` and `get_context`; deeper access goes through a module | read |
| luna_pinyin's speller already applies `pinyin:/spelling_correction` and `pinyin:/key_correction` (`hoa` → hao, `tain` → tian); `translator/enable_correction` loads a `.correction.bin` that 1.17's dictionary compiler never writes (the code is under `#if 0`), and the session aborts on the missing file | Chinese spelling correction comes from the schema's rules; `enable_correction` stays off | host-tested, corpus T01-012, T01-015 |
| Fuzzy pinyin and double pinyin are `speller/algebra` rules in the schema | changing a fuzzy-pinyin switch rewrites the schema and redeploys it, so deployment time matters | read |
| A reference ending in `?` is optional (`__include: kotomo_fuzzy:/patch?`): a missing file leaves the node unchanged, and config files resolve from the user directory before the shared one; `speller/algebra/+` appends to the list luna_pinyin assembles from `pinyin.yaml` | Kotomo's patch includes the app's `kotomo_fuzzy.yaml` from the user directory; the prebuilt data (no file) is unchanged, and the private schema gets the same rules through the same patch | host test (`FuzzyRimeTest`), corpus T08 |
| `fuzz/…/…/` derives a spelling marked fuzzy and halves its weight (`log 0.5`); an abbreviation rule only reaches spellings that exist when it runs | fuzzy rules use `fuzz`, and luna_pinyin's two abbreviation rules are appended again after them; between words of similar frequency the exact spelling wins, but a far more frequent fuzzy word can still come first (`zi` with z/zh on: 之 before 子) | corpus T08-020–T08-023 |
| `Projection::Apply` runs each algebra rule over every spelling the earlier rules produced, and a derived spelling carries all the syllables its source already stood for, so two fuzzy rules that share a letter chain (with n/l and l/r on, `ri` also stood for ni: `rihao` → 你好). The auto-patch plugin patches every compiled resource with its `.custom` file, an included schema too, so a schema that includes `luna_pinyin_simp.schema` and names `luna_pinyin_simp.custom:/patch` again gets the patch twice; two schemas with the same `translator/prism` share one prism file, built by whichever deploys last | each fuzzy rule writes what it derives in capitals and one `xlit` lowers them after all of them, so no rule acts on another's result (decision 16: l stands for n and r, n and r never for each other); the private schema no longer names the patch, which it receives through its include. The earlier attempt with capitals (Q6) failed only because the private schema applied the rules twice into the shared prism | host probe of the prism; `FuzzyRimeTest` (both schemas); corpus T08-N21, T08-N22, T08-025, T08-026 |
| Trime builds librime with Gradle's CMake integration (NDK 30.0.16248370); fcitx5-android links static libraries from a separate prebuilder | both build routes are available | read |
| 1.17.0 builds for Android with NDK 30 and CMake 3.22.1 from Kotomo's own target lists (`core/rime/CMakeLists.txt`); every Boost use is header-only, so the Boost 1.92.0 headers suffice; without glog it uses `no_logging.h` | `libkotomo_rime.so`, about 2.9 MB stripped per ABI, 16 KB pages, JNI exports only; nothing typed can be logged | built (arm64-v8a, x86_64), host-tested |
| No runtime switch disables learning; `translator/enable_user_dict: false` stops the user dictionary from being created, so it is neither read nor written | sensitive fields select the schema `luna_pinyin_simp_private` | host test T12-S2 |
| The deployer reads `schema/schema_id` from the raw schema file before resolving `__include` and `__patch`; a schema that sets its ID only by patch is silently skipped | derived schemas write their `schema:` block literally | host-tested |
| `RimeDeployWorkspace` deploys synchronously and refuses sessions meanwhile (host: 5–15 s fresh, about 0.2 s unchanged; peak RSS 294 MB) | librime reads `<shared>/build` as prebuilt data; a session opens on it with an empty user directory and compiles nothing (host: 30 ms) | the app ships data compiled on a Linux host (`scripts/prebuild-rime.sh`, CI) and only unpacks it on the phone | host test |
| `RimeDeployService` deploys in its own process (`:deploy`) into a staging directory while the keyboard keeps its session on the previous build, then the keyboard swaps the new build in (PLAN §4.2); a session opens on a moved build without a deploy (host: 30 ms) and converts as before; only before the very first deploy does Chinese mode type letters directly, and the candidate bar says so | host-tested; device NOT_RUN |
| The session API (`set_input` and candidate iteration) costs about 0.2 ms per prefix on the host | enough for per-span use (PLAN §5.4) | host only |
| A deployed schema's prism (`build/<schema>.prism.bin`) is a double-array trie of every spelling the schema accepts; `Prism::CommonPrefixSearch` lists the spellings that start a string, and `QuerySpelling` gives each one's type (normal, fuzzy, abbreviation, completion) and whether a correction derived it; it maps read-only without a session | the coordinator takes pinyin syllables from this table (`rime_spellings.h`), so fuzzy rules and corrections apply as in Chinese mode and Kotomo carries no syllable list | host test (S6-spellings) |
| With the syllables joined by apostrophes (`ni'hao`) a session lists conversions of the whole run next to words for a prefix of it; a candidate of type `sentence` was composed from shorter words, the other types are dictionary entries | the coordinator keeps the candidates with one character per syllable and charges a composed run more, which is what tells `mian'jie` from a chance split like `mi'an'jie` | corpus through the coordinator (S6) |
| Submodules ignore the repository's `.gitattributes`, and CMake's `file(READ)`/`file(WRITE)` translate newlines on Windows | `core/rime/stage-data.cmake` writes the shared data with `configure_file(… NEWLINE_STYLE LF)`, byte-identical on every host | built on Windows and Linux |

## Mozc

| Point | Consequence | Checked |
|---|---|---|
| Google's code is BSD-3-Clause; the dictionary data carries its own notices (IPAdic under the NAIST and ICOT terms, a public-domain Okinawa dictionary, Google's additions) | the notices ship with the data | read |
| It builds only with Bazel (Bazelisk); the Android build (`docs/build_mozc_for_android.md`) produces 16 KB-aligned `libmozc.so` on macOS or Linux hosts only | Mozc's Android libraries are built on an x86_64 Linux host with `scripts/build-mozc.sh` | read, built |
| The stock JNI registers on Google's class `com.google.android.apps.inputmethod.libs.mozc.session.MozcJni` and exposes only `evalCommand` (a serialized `commands::Command`), `onPostLoad` and `getDataVersion`; the Android client is not open source | Kotomo writes its own client and C++ glue | read |
| `Segment::SegmentType` has `FREE`, `FIXED_BOUNDARY`, `FIXED_VALUE`, `SUBMITTED` and `HISTORY`; `ImmutableConverter::Resegment` keeps a `FIXED_VALUE` segment's value, lid and rid, for conversion requests only | a cross-language span can be pinned inside a Japanese conversion from converter-level glue; predictions cannot carry pinned spans | read |
| Releases are tags only (`3.35.6354` at the last check) | the submodule follows the latest tag | read |
| 3.35.6354 (`0136c357`) has no git submodules; its dependencies come through Bazel modules (abseil-cpp 20260107.1, protobuf 34.1) and `src/build_tools/update_deps.py` (Android NDK r29) | `git submodule update --init third_party/mozc` is enough; Bazel fetches the rest | built |
| The host build works on aarch64 Linux (Debian 13, gcc 14.2, Bazel 9.0.2 through Bazelisk 1.30.0); Bazel's `local_jdk` needs `JAVA_HOME` | host tests run in WSL on Windows on ARM64 | built |
| rules_android_ndk runs the NDK's clang when it fetches the NDK, and the NDK has only x86_64 Linux and macOS host tools; with an NDK present even host builds fail on aarch64 Linux | Android libraries are built on x86_64 Linux; the local build of 2026-11-10 (Debian 13) reproduced the hashes of the deleted CI run byte for byte | built |
| Bazel evaluates the NDK module extension (rules_android_ndk) once per server: when the NDK is fetched after a host build in the same server, the Android build finds no C++ toolchain ("No matching toolchains found") | `scripts/build-mozc.sh` fetches the NDK before its first Bazel command | built |
| `converter::Converter::ApplyConversion` is public; hand-built segments with a `FIXED_VALUE` segment keep the pinned value while Mozc segments and converts the rest | PLAN §5.4's pinned-span conversion works at the converter layer without its fallbacks: 池袋 pinned + `にかいにいこう` → 池袋に買いに行こう | host test |
| A `FIXED_BOUNDARY` segment stays one segment through `ApplyConversion`; prediction (`StartPrediction`, `PREDICTION`) completes a reading only with a mobile request (`mixed_conversion`) and, for a hiragana key without a composer, `use_already_typing_corrected_key` | segment shrinking and extending pin the boundary; `Predict` sends both (ありがと → ありがとう, 0.4 ms on the host) | host test |
| `DictionaryInterface::LookupExact` returns tokens with lid and rid (池袋/いけぶくろ: 1924/1924); a pinyin spelling has no entry | pinned spans take the ids of the same entry; unknown words take the general noun | host test |
| `//converter`, `//session:session_handler` and `//dictionary:dictionary_interface` are visible only inside Mozc | Kotomo's glue builds with `--nocheck_visibility` instead of a patch | built |
| Learning happens only when a conversion is committed; `Config.incognito_mode` and `Request.is_incognito_mode` disable all mutable operations | the glue never commits and sets both for sensitive fields | read, host test |
| The romaji `wa` for the particle は converts as わ: `watashiwanihonjin` → 私羽日本人 in a plain session | corpus line T03-001 needs the coordinator to handle it | host test |
| The composer's romaji table maps what it can and leaves other letters as ASCII (`card` → かrd); `nn` is ん, and a lone `n` becomes ん only before a consonant or at the end, so `konnichiwa` reads こんいちわ | the coordinator proposes kana edges from the table's shortest spellings and lets n + ni win over nn + i | host test, corpus through the coordinator (S6) |
| Candidates of a free segment carry a cost that includes connection (あい 5194, 日本 4211, 買いに行こう 8339 after に); a `FIXED_VALUE` segment reports a large negative cost | the coordinator adds Mozc's cost for free segments and takes the lexicon's word cost plus an average connection share for pinned words | corpus through the coordinator (S6) |
| Pinning は between two free spans (`わたし`, は, `にほんじん`) converts to 私は日本人, at a lower total cost than わたしわにほんじん (私羽日本人) | the particle rule (wa → は, o → を, e → へ) is a pinned span, and Mozc's costs choose between the two readings | corpus line T03-001 through the coordinator (S6) |
